# 接口测试用例标准说明

本文件定义**接口测试**场景下的用例设计维度与输出要求。与SKILL中的通用策略（正向、反向、边界值、等价类等）配合使用；生成接口测试用例时，除通用策略外须遵循以下要求。

---
## 一、接口测试覆盖维度

### 1.1 请求方法测试

**正确方法**
- 使用文档规定的HTTP方法（GET/POST/PUT/DELETE等）调用接口
- 验证返回状态码和数据格式符合预期

**错误方法**
- 使用非预期的方法调用（如用GET调用POST接口）
- 预期返回405 Method Not Allowed或文档定义的错误

### 1.2 URL与路径测试

**正确路径**
- 使用正确的接口路径调用
- 验证返回成功

**错误路径**
- 路径拼写错误、大小写错误、缺少路径参数
- 预期返回404 Not Found或文档定义的错误

### 1.3 请求参数测试

**参数类型验证**
- 每个参数的数据类型（string/int/boolean/array/object）
- 类型不匹配时的处理

**参数必填性验证**
- 必填参数缺失
- 必填参数传空值/null
- 可选参数不传/传null

**参数格式验证**
- 日期格式（YYYY-MM-DD HH:mm:ss等）
- 手机号、邮箱等正则格式
- 枚举值范围

**参数长度/范围验证**
- 字符串长度边界（最小、最大、超长）
- 数值范围边界（最小值、最大值、边界外）
- 数组元素数量边界

### 1.4 请求头测试

**Content-Type**
- 正确的Content-Type（application/json等）
- 错误的Content-Type
- 缺失Content-Type

**认证信息**
- 正确的Token/Session
- 过期/无效的Token
- 缺失认证信息
- 权限不足的Token

### 1.5 响应测试

**成功响应**
- HTTP状态码（200/201等）
- 响应数据结构符合接口文档
- 关键字段值正确
- 响应时间符合要求

**失败响应**
- 错误状态码（400/401/403/404/500等）
- 错误信息明确、符合文档定义
- 错误码与错误信息对应关系正确

**响应头验证**
- Content-Type正确
- 必要的自定义头存在

### 1.6 业务逻辑测试

**状态流转**
- 不同初始状态下调用接口的行为
- 状态变更后的数据一致性

**幂等性**
- 重复调用接口的结果一致性（适用于POST/PUT）

**并发测试**
- 并发调用接口的数据一致性
- 锁机制是否生效

### 1.7 安全测试

**SQL注入**
- 在参数中尝试SQL注入语句
- 验证被正确过滤或转义

**XSS攻击**
- 在参数中尝试XSS脚本
- 验证被正确过滤或转义

**敏感信息**
- 响应中是否泄露敏感信息（密码、密钥等）
- 日志中是否记录敏感信息

## 二、输出时的表述要求

### 2.1 用例标题

格式：「接口名-场景-预期结果」

示例：
- "用户登录-正确账号密码-返回Token和用户信息"
- "用户登录-密码错误-返回401和密码错误提示"
- "创建订单-缺少必填参数手机号-返回400和参数缺失提示"

### 2.2 接口信息

| 字段 | 说明 |
|------|------|
| 接口名称 | 接口的功能描述 |
| 请求方法 | GET/POST/PUT/DELETE等 |
| 接口路径 | 完整的URL路径 |
| 接口描述 | 接口的业务功能描述 |

### 2.3 请求信息

| 字段 | 说明 |
|------|------|
| 请求头 | Content-Type、Authorization等 |
| 请求参数 | Query参数或Body参数 |
| 参数类型 | 每个参数的数据类型 |
| 参数说明 | 必填性、取值范围、示例值 |

### 2.4 预期结果

| 字段 | 说明 |
|------|------|
| HTTP状态码 | 200/400/401等 |
| 响应数据结构 | 返回的JSON结构 |
| 关键字段值 | 关键字段的期望值 |
| 响应时间 | 性能要求（如有） |
| 数据库变更 | 预期的数据库变更 |

---
## 三、与通用策略的映射

| 通用策略 | 在接口测试中的应用 |
|----------|-------------------|
| 正向用例 | 正确参数、正确路径、正确方法、成功响应 |
| 反向/异常用例 | 参数错误、路径错误、方法错误、认证失败、权限不足 |
| 边界值 | 参数长度边界、数值范围边界、数组数量边界 |
| 等价类 | 参数类型的有效/无效等价类、枚举值选取 |
| 状态流转 | 不同状态下调用接口的行为 |

---
## 四、用例字段建议

| 字段 | 说明 | 必填 |
|------|------|------|
| 用例ID | 唯一标识，如TC-API-001 | 是 |
| 接口名称 | 接口功能描述 | 是 |
| 请求方法 | GET/POST/PUT/DELETE等 | 是 |
| 接口路径 | 完整的URL路径 | 是 |
| 用例标题 | 概括测试场景 | 是 |
| 用例类型 | 正向/反向/边界/异常/安全 | 是 |
| 优先级 | P0/P1/P2 | 是 |
| 前置条件 | 数据准备、环境要求 | 是 |
| 请求头 | Content-Type、Authorization等 | 是 |
| 请求参数 | Query/Body参数及值 | 是 |
| 预期状态码 | HTTP状态码 | 是 |
| 预期响应 | 响应数据和结构 | 是 |
| 数据库断言 | 预期的数据库变更 | 否 |
| 备注 | 补充说明 | 否 |
