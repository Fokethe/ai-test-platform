# 性能测试用例标准说明

本文件定义**性能测试**场景下的用例设计维度与输出要求。当需求文档中包含性能指标（响应时间、吞吐量、并发量等）时，除通用测试策略外，须遵循以下要求生成性能测试用例。

---
## 一、性能测试类型

### 1.1 负载测试（Load Testing）

**目的**
验证系统在正常和峰值负载下的性能表现，确定系统的最大承载能力。

**测试场景**
- 基准负载：模拟正常业务量的并发用户数
- 峰值负载：模拟业务高峰期的并发用户数
- 逐步加压：从低到高逐步增加负载，观察性能变化

**关注指标**
- 响应时间（平均、最大、百分位值）
- 吞吐量（TPS/QPS）
- 错误率
- 资源利用率（CPU、内存、磁盘IO、网络）

### 1.2 压力测试（Stress Testing）

**目的**
验证系统在极端负载下的稳定性和恢复能力，找出系统崩溃的临界点。

**测试场景**
- 超载测试：超过系统设计最大负载的并发
- 长时间高负载：持续高负载运行，观察内存泄漏等问题
- 突发流量：瞬间大量请求涌入

**关注指标**
- 系统是否崩溃或响应严重超时
- 错误率是否急剧上升
- 系统恢复能力（负载降低后能否恢复正常）

### 1.3 稳定性测试（Endurance Testing）

**目的**
验证系统在长时间运行下的稳定性，发现内存泄漏、连接池耗尽等问题。

**测试场景**
- 7×24小时持续运行
- 正常负载下长时间运行

**关注指标**
- 内存使用量是否持续增长
- 连接数是否持续增长
- 响应时间是否逐渐变长
- 错误率是否逐渐上升

### 1.4 并发测试（Concurrency Testing）

**目的**
验证系统在并发访问下的数据一致性和功能正确性。

**测试场景**
- 多用户同时操作同一数据
- 并发读写
- 并发事务

**关注指标**
- 数据一致性（是否出现脏读、幻读）
- 锁竞争导致的性能下降
- 死锁情况

### 1.5 容量测试（Volume Testing）

**目的**
验证系统在处理大量数据时的性能表现。

**测试场景**
- 大数据量查询
- 大批量数据导入
- 大数据量报表生成

**关注指标**
- 响应时间是否随数据量增长而显著增加
- 内存使用是否合理

## 二、性能指标设计

### 2.1 响应时间指标

| 指标 | 说明 | 常见阈值 |
|------|------|----------|
| 平均响应时间 | 所有请求的平均耗时 | < 200ms（接口）< 3s（页面） |
| 最大响应时间 | 最慢请求的耗时 | < 1s（接口）< 10s（页面） |
| P50响应时间 | 50%请求低于该值 | < 100ms |
| P95响应时间 | 95%请求低于该值 | < 500ms |
| P99响应时间 | 99%请求低于该值 | < 1s |

### 2.2 吞吐量指标

| 指标 | 说明 | 单位 |
|------|------|------|
| TPS | 每秒事务数 | transactions/sec |
| QPS | 每秒查询数 | queries/sec |
| 吞吐量 | 每秒处理的数据量 | MB/s |

### 2.3 并发指标

| 指标 | 说明 |
|------|------|
| 并发用户数 | 同时在线操作用户数 |
| 并发连接数 | 同时建立的连接数 |
| 并发请求数 | 同时处理的请求数 |

### 2.4 资源利用率指标

| 指标 | 说明 | 建议阈值 |
|------|------|----------|
| CPU使用率 | 服务器CPU利用率 | < 80% |
| 内存使用率 | 服务器内存利用率 | < 80% |
| 磁盘IO | 磁盘读写速率 | 视磁盘类型而定 |
| 网络带宽 | 网络传输速率 | < 70%带宽 |

## 三、性能测试用例设计

### 3.1 用例设计原则

**基于业务场景**
- 优先测试核心业务场景（如下单、支付）
- 优先测试高频访问接口
- 考虑业务高峰期的场景组合

**基于性能风险**
- 复杂查询接口
- 大数据量处理接口
- 涉及外部依赖的接口
- 有同步阻塞操作的接口

### 3.2 负载模型设计

**逐步加压模型**
```
0用户 → 50用户 → 100用户 → 200用户 → 500用户
每阶段持续5分钟，观察性能变化
```

**阶梯加压模型**
```
持续增加负载直到系统性能下降或出错
用于找出系统最大承载能力
```

**脉冲加压模型**
```
正常负载 → 突发高负载 → 正常负载
用于测试系统的突发流量处理能力
```

**稳定性模型**
```
持续正常负载运行24小时或更长时间
用于发现内存泄漏等问题
```

## 四、输出时的表述要求

### 4.1 用例标题

格式：「测试场景-负载模型-关注指标」

示例：
- "用户下单接口-逐步加压至500并发-响应时间和TPS"
- "数据库查询-大数据量-查询响应时间和内存使用"
- "系统稳定性-24小时持续运行-内存泄漏检测"

### 4.2 测试场景描述

| 字段 | 说明 |
|------|------|
| 测试目的 | 本次性能测试的目标 |
| 测试范围 | 涉及的接口/功能/模块 |
| 负载模型 | 并发用户数、加压方式、持续时间 |
| 测试数据 | 数据量、数据分布 |
| 环境配置 | 服务器配置、网络环境、数据库配置 |

### 4.3 性能指标

| 字段 | 说明 |
|------|------|
| 预期TPS | 期望达到的每秒事务数 |
| 预期响应时间 | 期望的响应时间（平均、P95、P99） |
| 最大并发 | 系统设计支持的最大并发数 |
| 错误率阈值 | 可接受的错误率上限 |
| 资源阈值 | CPU、内存等资源使用上限 |

### 4.4 测试步骤

1. 准备测试环境和数据
2. 配置性能测试工具（JMeter、LoadRunner等）
3. 执行负载测试，收集性能数据
4. 分析性能瓶颈
5. 优化后重新测试验证

---
## 五、用例字段建议

| 字段 | 说明 | 必填 |
|------|------|------|
| 用例ID | 唯一标识，如TC-PERF-001 | 是 |
| 用例标题 | 测试场景描述 | 是 |
| 测试类型 | 负载/压力/稳定性/并发/容量 | 是 |
| 测试目的 | 为什么要做这个测试 | 是 |
| 测试范围 | 涉及的接口/模块 | 是 |
| 负载模型 | 并发数、加压策略、持续时间 | 是 |
| 测试数据 | 数据量和数据特点 | 是 |
| 预期指标 | TPS、响应时间、错误率等 | 是 |
| 通过标准 | 什么情况下认为测试通过 | 是 |
| 环境要求 | 服务器配置、网络要求 | 否 |
| 备注 | 补充说明 | 否 |
