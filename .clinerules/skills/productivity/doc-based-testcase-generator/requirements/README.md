# requirements/ 需求概述文件夹

本文件夹用于存放**需求概述文本**，作为生成测试用例的输入源。

## 用途

当用户需要基于已有需求文档生成测试用例时，可以将需求概述文本放入此文件夹，供 skill 读取和分析。

## 文件格式

- **Markdown (.md)** - 推荐格式，适合结构化需求文档
- **文本 (.txt)** - 纯文本格式，适合快速记录
- **JSON (.json)** - 结构化数据，适合接口定义等

## 文件命名规范

建议采用以下命名格式：

```
<项目名称>_<模块名称>_<日期>.md
<项目名称>_<模块名称>_PRD_<版本>.md
<项目名称>_接口文档_<日期>.md
```

示例：
- `电商系统_订单管理_20250310.md`
- `支付平台_核心接口_PRD_v1.2.md`
- `用户中心_登录注册接口_20250310.md`

## 内容格式建议

### 功能需求文档

```markdown
# 需求概述

## 功能模块
- 模块名称：xxx
- 功能描述：xxx

## 业务流程
1. 步骤一
2. 步骤二
3. 步骤三

## 输入约束
- 字段A：必填，长度1-20字符
- 字段B：可选，格式为手机号

## 状态流转
- 初始状态 → 操作 → 目标状态

## 性能要求
- 响应时间 < 200ms
- 支持 1000 QPS
```

### 接口文档

```markdown
# 接口概述

## 接口信息
- 路径：/api/v1/xxx
- 方法：POST
- 描述：xxx

## 请求参数
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | string | 是 | 名称，1-20字符 |
| age | int | 否 | 年龄，0-150 |

## 响应格式
```json
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

## 错误码
| 错误码 | 说明 |
|--------|------|
| 1001 | 参数错误 |
| 1002 | 权限不足 |
```

## 使用流程

1. **准备需求文档**：将 PRD、接口文档等保存到本文件夹
2. **执行 skill**：AI 读取 requirements/ 下的文件
3. **生成测试用例**：基于文档内容生成结构化测试用例
4. **保存结果**：将生成的测试用例保存到 testcases/ 目录

## 注意事项

- 需求文档应尽量完整，包含约束条件和边界说明
- 多个相关文档可以放在一起，skill 会综合分析
- 敏感信息（如真实账号、密码）应脱敏后再放入
