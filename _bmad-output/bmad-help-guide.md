## 🏗️ 系统架构概览

BMAD 是一个模块化、多代理协作的软件开发方法论，包含以下核心模块：

| 模块     | 全称                         | 用途                         | 版本  |
| -------- | ---------------------------- | ---------------------------- | ----- |
| **core** | Core System                  | 核心系统，提供基础技能和工具 | 6.2.0 |
| **bmm**  | BMAD Method                  | 完整软件开发方法论 (推荐)    | 6.2.0 |
| **bmb**  | BMAD Builder                 | 智能体和工作流构建器         | 1.0.2 |
| **cis**  | Creative Intelligence Suite  | 创意智能套件                 | 0.1.8 |
| **gds**  | Game Dev Studio              | 游戏开发工作室               | 0.2.2 |
| **tea**  | Test Architecture Enterprise | 测试架构企业版               | 1.7.0 |
| **wds**  | Whiteport Design System      | Whiteport 设计系统           | 0.3.0 |

## 👥 角色定义 (BMM 模块)

每个角色都有独特的个性、专业技能和工作方式：

### 📊 Mary - 业务分析师

```
名称: Mary | 图标: 📊 | 命令前缀: bmad:bmm:*
```

**专业领域**: 市场调研、竞争分析、需求获取、领域专业知识
**沟通风格**: 像寻宝猎人一样兴奋，善于发现模式和洞察
**核心原则**:

- 运用波特五力、SWOT 等分析框架
- 基于可验证证据的发现
- 精确表达需求，确保所有利益相关者的声音被听到

**可用命令**:
| 命令 | 功能 |
|------|------|
| `BP` | 项目头脑风暴 |
| `MR` | 市场调研 |
| `DR` | 领域研究 |
| `TR` | 技术研究 |
| `CB` | 创建产品简报 |
| `DP` | 项目文档化 |

### 📋 John - 产品经理

```
名称: John | 图标: 📋 | 命令前缀: bmad:bmm:*
```

## 🔄 标准工作流 (BMM)

### 阶段 1: 分析 (Analysis)

```
顺序: 任意 (anytime)
角色: Mary (业务分析师)
```

| 步骤 | 命令 | 名称         | 必需 | 输出         |
| ---- | ---- | ------------ | ---- | ------------ |
| 1    | `BP` | 项目头脑风暴 | 否   | 头脑风暴报告 |
| 2    | `MR` | 市场调研     | 否   | 研究文档     |
| 3    | `DR` | 领域研究     | 否   | 研究文档     |
| 4    | `TR` | 技术研究     | 否   | 研究文档     |
| 5    | `CB` | 创建产品简报 | 否   | 产品简报     |

---

### 阶段 2: 规划 (Planning)

```
顺序: 10 → 20 → 25 → 30
角色: John (产品经理) + Sally (UX 设计师)
```

| 顺序 | 命令 | 名称         | 必需  | 输出         |
| ---- | ---- | ------------ | ----- | ------------ |
| 10   | `CP` | 创建 PRD     | ⭐ 是 | PRD 文档     |
| 20   | `VP` | 验证 PRD     | 否    | 验证报告     |
| 25   | `EP` | 编辑 PRD     | 否    | 更新后的 PRD |
| 30   | `CU` | 创建 UX 设计 | 否    | UX 设计      |

---

### 阶段 3: 解决方案 (Solutioning)

```
顺序: 10 → 30 → 70
角色: Winston (架构师) + John (产品经理)
```

| 顺序 | 命令 | 名称               | 必需  | 输出               |
| ---- | ---- | ------------------ | ----- | ------------------ |
| 10   | `CA` | 创建架构           | ⭐ 是 | 架构文档           |
| 30   | `CE` | 创建 Epic 与 Story | ⭐ 是 | Epic 与 Story 列表 |
| 70   | `IR` | 检查实现就绪度     | ⭐ 是 | 就绪度报告         |

---

### 阶段 4: 实现 (Implementation)

```
顺序: 10 → 20 → 30 → 35 → 40 → 50 → 60 (循环)
角色: Bob (SM) → Amelia (Dev) → Bob (SM)
```

| 顺序 | 命令 | 名称          | 必需  | 说明                   |
| ---- | ---- | ------------- | ----- | ---------------------- |
| 10   | `SP` | Sprint 规划   | ⭐ 是 | 生成开发任务计划       |
| 20   | `SS` | Sprint 状态   | 否    | 汇总状态并路由         |
| 30   | `CS` | 创建 Story    | ⭐ 是 | 准备下一个待处理 Story |
| 35   | `VS` | 验证 Story    | 否    | 验证 Story 就绪度      |
| 40   | `DS` | 开发 Story    | ⭐ 是 | 执行 Story 实现        |
| 45   | `QA` | QA 自动化测试 | 否    | 生成自动化测试         |
| 50   | `CR` | 代码审查      | 否    | 若发现问题回到 DS      |
| 60   | `ER` | 回顾复盘      | 否    | Epic 结束时可选        |

**Story 周期流程**:

```
CS → VS → DS → CR
       ↑    ↓
       └────┘ (如需修复回到 DS)
```
