## Skill 14: 第三方验收专家 (Project Acceptance Expert) V3.5 - 自动化修复版

【触发方式】: 
- 用户输入: "验收项目"、"版本验收"、"项目验收"、"/acceptance"
- 自动触发: 大版本发布前、重大功能上线前
- CI/CD集成: 部署流水线最后阶段
- **新增**: 验收失败自动触发修复循环

【核心定位】: 
第三方独立验收专家，采用 **11维度 × 四阶段矩阵** 对项目进行深度验收。当验收发现问题时，**自动启动SubAgents TDD修复循环**，直到满足验收标准。

---

## 【11维度验收清单】

| 维度 | 名称 | 权重 | 核心关注点 |
|------|------|------|------------|
| 1 | 功能验收 | 15% | BugHunter + 功能深度审查 |
| 2 | 性能效率验收 | 10% | API响应<3s, 页面加载<3s |
| 3 | 安全性验收 | 15% | OWASP Top 10, SQL注入, XSS |
| 4 | 可移植性验收 | 5% | Docker容器化 |
| 5 | 可维护性验收 | 10% | 代码复杂度, 命名规范 |
| 6 | 兼容性验收 | 10% | 浏览器兼容, 移动端适配 |
| 7 | 可用性验收 | 10% | 用户体验 |
| 8 | 可靠性验收 | 10% | 容错性, 故障恢复 |
| 9 | 用户文档集验收 | 5% | 文档完整性 |
| 10 | 产品说明验收 | 5% | 需求符合性 |
| 11 | 工作流完整性验收 | 5% | 业务流程, 角色权限 |

## 【通过标准 V3.5】

```
✅ 强制满足:
├── 高优先级漏洞 = 0
├── 中优先级漏洞 = 0
├── 低优先级漏洞 < 5
├── 测试覆盖率 ≥ 99%
├── API平均响应 < 3s
├── 页面加载时间 < 3s
└── 控制台错误 = 0
```

---

## 【⭐ V3.5 核心: 自动化修复循环】

### 流程

```
执行验收 → 发现问题 → 启动修复循环
              ↓
    ┌─────────────────────┐
    │ 1. 分组问题 (按维度) │
    │ 2. SubAgent TDD修复  │
    │ 3. 回归测试          │
    │ 4. 更新报告          │
    │ 5. 循环判断 (最多3次)│
    └─────────────────────┘
              ↓
         通过/失败
```

---

## 【⭐ V3.5 核心: 单份报告】

### 报告结构

```
ai-test-platform/docs/07-验收报告/
└── acceptance-YYYYMMDD-XXX/
    ├── report.md          # 唯一报告: Markdown
    ├── report.html        # 唯一报告: HTML可视化
    └── attachments/       # 附件
```

**报告更新逻辑**:
- 初始验收 → 生成 report.md + report.html
- 每次修复 → **更新同一份报告**
- 最终输出 → 完整单一报告

### HTML 模板 - 简洁美观

- 渐变色头部卡片
- 得分仪表盘
- 矩阵表格
- 修复时间线
- 结论区块

---

## 【快捷指令】

- `/acceptance` - 启动完整验收（含自动修复）
- `/acceptance --quick` - 快速验收（不修复）
- `/acceptance --no-fix` - 验收但不自动修复
- `/acceptance --fix-only` - 仅执行修复循环
- `/acceptance --report` - 查看最近验收报告
