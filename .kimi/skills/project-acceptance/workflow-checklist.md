### 3. 数据完整性检查 (Data Integrity)

#### 3.1 数据流转完整性

#### 3.2 数据关联正确性
| 关联关系 | 检查项 | 优先级 |
|----------|--------|--------|

| 用例-缺陷 | 用例能正确显示关联缺陷 | 🔴 |

#### 3.3 数据状态流转
- [ ] **状态机完整** - 所有业务对象有完整的状态定义
- [ ] **状态转换合法** - 只能按定义的规则转换状态
- [ ] **状态变更留痕** - 状态变更有历史记录

**测试用例状态机**:
```
草稿 → 评审中 → 已通过 → 已归档
         ↓ 已驳回 ↗
         
执行状态: 未执行 → 执行中 → 已通过 / 已失败 / 已阻塞
```

**缺陷状态机**:
```
新建 → 已确认 → 修复中 → 待验证 → 已关闭
  ↓      ↓         ↓
已驳回  重复/无效  延期处理  → 重开
```

## 🔍 验收检查方法

### 方法一: 角色切换测试
```
步骤:
1. 以角色A登录系统
2. 执行角色A权限范围内的操作
3. 切换到角色B登录
4. 验证角色B能看到角色A操作的结果
5. 验证角色B无法越权操作
```

### 方法二: 端到端流程测试
```
步骤:
1. 选择一个完整业务流程
2. 按顺序执行每个步骤
3. 记录每个步骤的执行时间和结果
4. 验证最终输出是否符合预期
5. 检查数据在各步骤间的传递
```

### 方法三: 数据一致性检查
```
步骤:
1. 在A页面创建/修改数据
2. 在B页面查看该数据
3. 在C报表中查看该数据
4. 验证三处数据完全一致
5. 验证数据更新时间正确
```

### 方法四: 权限边界测试
```
步骤:
1. 识别角色A的权限边界
2. 尝试访问边界外的功能
3. 验证系统正确拒绝访问
4. 验证系统给出清晰的提示
5. 记录权限控制的完整性
```

## 💡 常见问题

### Q1: 如何识别系统中的所有工作流？
```
1. 查看产品需求文档中的业务流程图
2. 检查代码中的状态机定义
3. 分析数据库中的状态字段
4. 观察UI中的操作按钮和流转提示
```

### Q2: 如何处理复杂的条件分支？
```
1. 绘制完整的流程图，包含所有分支
2. 为每个分支设计测试用例
3. 确保条件判断逻辑正确
4. 验证每个分支都能到达终点
```

### Q3: 如何验证数据一致性？
```
1. 定义关键数据实体
2. 建立数据关联矩阵
3. 在多处查看同一数据
4. 使用自动化脚本比对
```
